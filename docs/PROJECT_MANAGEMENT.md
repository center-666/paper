# 项目管理

此仓库的目标是管理可审阅、可复核的论文源码和研究结论，同时避免把本地完整研究环境误作公开发布包。

## 内容分层

- `papers/`：两篇作者稿的精选快照，包含编辑源、作者制作的图表/PDF、少量复现输入和版本状态。
- `research/`：面向仓库读者整理的当前状态、候选比较和 42 篇文献证据矩阵/BibTeX。原始 `literature_review/` 保留在本地作为完整研究档案，不整棵公开推送。
- `simulation/`：模型、估计/攻击引擎、预注册计划、依赖锁定和本地小规模验证代码。完整实验轨迹目录已忽略；被版本管理的精选报告、计划和汇总表保留在其原有 `runs/validation_runs/checks/` 路径，其余输出仍为本地资产。
- `simulation/runs/`、`simulation/validation_runs/`、`simulation/exploration_runs/`、`simulation/checks/`：保留少量精选报告、计划、汇总表和审计 JSON；完整 per-seed 轨迹、NPZ 和逐试验中间数据不随 Git 发布。
- `research/provenance/`：旧目录选定证据资产的相对路径与 SHA-256 索引，可核对来源而不复制整个历史树。

本机 `literature_review/` 另含 Zotero 条目键、PDF/全文抽取、抓取响应和旧审计快照，因此默认不纳入 Git。仓库中的 `papers/snapshot_manifest.json` 只记录两个精简稿件快照的来源相对路径和哈希。

## 版本边界

- 论文快照保持原作者版本；新改动在仓库中的快照上进行，并同步其日期、状态和来源哈希。
- 文件名含日期的 `*_plan.json` 是对应运行的固定计划。不要改写既有运行的计划、测试样本或摘要；新验证使用新的日期/RunId 目录。
- 结果报告应说明独立统计单位、样本共享方式、错误/失败运行和输出审计。多条方法轨迹不等于独立样本数。
- 旧 `第二篇小论文/` 是历史工作区；本仓库对它只保存精选快照，不在原树中重排、重命名或覆盖文件。

## 大文件与外部资料

Git 忽略 `.venv/`、原始压缩包、原始旧论文树、第三方 PDF/全文、Zotero 数据库、完整估计轨迹、`.npz/.npy/.mat` 中间数据和 LaTeX 临时文件。作者自己的论文 PDF 可放在精选稿件目录；第三方论文 PDF 不应提交到公开仓库。

被忽略的本地材料仍可从原工作区读取。报告中的相对路径若指向这些材料，在公开仓库可能无法打开；请以 DOI/出版社入口或本地 Zotero 附件为准。SHA-256 清单可用于本机核对，但不能恢复已忽略的数据。

## 日常维护

1. 先更新 `papers/<paper>/` 中的源文件，再更新该稿 `README.md` 的日期、状态、复现方法和未决项。
2. 新仿真先冻结计划与种子划分。保留原始运行目录；只将结论、计划、配置、汇总表和 `output_audit.json` 纳入跟踪，完整轨迹留在本地忽略目录。
3. 文献只记录读过的证据等级。新增全文时更新下载登记和文献矩阵；不要把摘要命中写成全文核查。
4. 提交前运行 `git status --short`、`git diff --cached --stat` 和忽略项核查；确认无原始 Zotero 数据、第三方全文、密钥或意外大文件。
5. 论文进入导师/投稿版本后更新稿件状态，不覆盖历史快照；保留可复核的来源 SHA-256。

本仓库暂未设置许可证。公开可见不代表对第三方资料的再分发授权。
