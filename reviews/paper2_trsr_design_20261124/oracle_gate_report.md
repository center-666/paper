# TRSR Oracle 潜力试验与阶段裁决

2026-11-24。**零延迟的方向效率达到预设探索门槛；工程上继续开发完整审计器的依据不足。** 在 64 拍主窗中，立即启动 TRSR 可捕获直接 Oracle 条件改善的 37.49%；延迟 20 拍只剩零延迟 TRSR 条件改善的 2.83%。建议先审查能否在有效窗口内获得可靠约束，以及重放相对同信息 Direct 能增加什么，再决定是否投入在线系统。[预登记与前一轮归档](oracle_registration.md) · [理论及证明](theory_oracle_gate.md) · [结果图](results/oracle_v1/oracle_gate.pdf)

## 1. 统计口径

依照分支预先指定的固定起点 80，使用 8 个有符号幅值与持续时间组合，各 200 个独立 episode。每个 episode 共用外生过程、测量、中心偏移和触发均匀数构造受污染与健康 sham 的配对；两者各自用 Monitor 生成其实际记录。所有方法在同一条件内复用同一份记录。只有评估器见真值。窗口及污染响应由 Oracle 提供给 M2–M5。M1 也从已知的同一恢复时刻启动。原始记录中的模拟偏差仅用于离线评价 V2 估计器。

计分量为 Monitor 累计加权平方损失减去方法的对应损失，正值有利。主窗口为停止后前 64 拍，补充窗口为 512 拍。八组等权，对每组先形成 episode 级配对差，再以分层标准误和 Welch–Satterthwaite 自由度给出诊断性 95% 区间。等待时间在同一记录上重复计分，不能增加独立样本数。约 48,000 行窗口统计来自 1,600 对 episode（3,200 条受攻或 sham 轨迹）。[参数协议](trsr_protocol.json) · [原始逐轨迹窗口数据](results/oracle_v1/episodes.csv.gz)

## 2. 立即恢复及其信息代价

| 方法 | 64 拍平均累计损失 | 相对 M0 的实际降损 [95% 配对区间] | 平均累计条件改善 |
|---|---:|---:|---:|
| M0 正常使用所有接收数据 | 39.02663 | 0 | 0 |
| M1 检查点持续开环外推 | 21588.46 | −21549.44 [−23435.80, −19663.07] | −21547.46 |
| M2 可疑窗口完全重放 | 39.15252 | −0.12588 [−0.19550, −0.05627] | −0.20423 |
| M3 Monitor 与重放各半 | 39.03480 | −0.00816 [−0.04258, 0.02625] | −0.04733 |
| M4 真窗口、真偏差、自适应权重 | 38.99247 | **0.03417 [0.01259, 0.05574]** | **0.01352** |
| M5 真参数直接污染校正 | 39.00390 | 0.02273 [−0.01412, 0.05959] | 0.03607 |

M4 的主指标相对 M0 总累计损失仅约 **0.0875%**。在同一批记录上，M4 对 M2、M3 的平均配对降损分别为 0.16005 [0.10248, 0.21762] 和 0.04233 [0.01692, 0.06774]。M4 对 M5 的样本降损为 0.01143 [−0.01593, 0.03880]。后者包含零，且理论和同记录条件比较均以 M5 为上限。M5 的理论优势针对给定记录的条件期望；单次轨迹仍受不可见状态误差影响。沿重放正向射线最多捕获 40.41% 的理想条件改善，限幅到 [0,1] 后为 37.49%。

- 预指定的 −0.25、60 拍组平均降损 0.05218 [−0.03302, 0.13737]，条件收益份额 35.32%；+0.25、60 拍组为 0.06115 [−0.02066, 0.14296]、36.64%。两组都符合“平均降损为正且份额至少 20%”的原始筛选条件，各自的组内区间均跨零。
- −0.10、20 拍组的平均降损为 −0.00529；全部八组的区间均跨零。图 A 逐组展示全部结果，主效应使用预设的八组等权汇总。
- 受攻记录在 64 拍中有 559/1600 条（34.94%）从未发布非零 M4 动作，535/1600 条（33.44%）实际损失高于 Monitor。所有记录计入汇总。健康 sham 的已知偏差为零，所以 M4 全部选择 Monitor。该项仅验证零偏差行为，在线误报警/误恢复率有待实际审计数据测量。
- 512 拍零延迟 M4 的实际降损为 0.03417 [0.01259, 0.05575]。本批多数收益已出现在前 64 拍。先前随机起点、仅正幅值的 800 条试验使用不同种子和不同预设窗口，其原 512 拍结果为 0.00807 [−0.01901, 0.03516]，不能把两项试验当作同一协议下的确认性复现。[新试验分组及窗口明细](results/oracle_v1/summary.json)

## 3. 延迟留给恢复器的实际空间

下表一律对齐真实停止后的原 64 拍。两列百分数的分母分别为 M5 和 M4 在零延迟时的平均累计条件改善。

| 等待（拍） | M4 实际平均降损 [95% 配对区间] | M5 剩余能量 / M5 原能量 | M4 条件收益 / M4 原收益 |

延迟 128 拍时主窗已结束。对仍可动作的补充 512 拍窗口，延迟 128 拍后的平均 M5 条件能量仅约 \(2.74\times10^{-14}\)。即使采取真参数的最优直接校正，等待也会耗尽大部分机会。当前数据不能确定可部署审计器多久才能排除零污染解释。[完整延迟曲线与预选案例](results/oracle_v1/oracle_gate.pdf)

## 4. 理论、实现与复核

| 检验 | 对应实现与验证 | 已取得的证据 |
|---|---|---|
| 有限窗口污染与停止后衰减 | V2Filter.response、独立有理数 Joseph 更新与 Stage 6 收缩证书 | 216 个夹具时刻核对显式窗口与两个永久响应之差、校正后均值及工作标签；停止后能量的延迟上限见命题 1 |
| 恢复方向 | V2Filter.replay 及完整前缀 | 在同记录上测试空区间、全部与部分擦除、静默中心、窗外载荷和早晚合法检查点。M2 工作协方差只用于选取更新增益 |
| 可行性与效率 | decide、非对角 W、实际浮点位移、8193 点一维权重遍历 | 正最坏条件改善当且仅当 \(q>0,\ g>0\)。候选集收缩时的单调性要求固定重放方向。相同幅度约束下，任意向量 Direct 的最优条件改善至少等于线段法 |
| 置信覆盖与在线安全 | 理论命题 3 | 以共同记录、正确模型、可靠支撑下界和真实候选全时域覆盖为前提。Oracle 浮点验证不产生在线覆盖证书 |
| 输出与统计 | 独立标量入口、全部轨迹重算、同种子重放 | 8 项测试通过。接收器夹具在新随机运行前通过，另加的完整入口夹具在初次运行后通过；其后独立重跑，四个数值输出文件逐字节一致 |

程序检查以 binary64 实际输出为对象，有限误差容限为诊断口径。接收器与 Oracle 生成/离线打分分文件维护。时延遮罩利用的是“窗口固定、完整重放、后续增量递推相同、发布不回写”的等价性；它不测延后启动时的在线执行成本。计时覆盖八次各 400 条轨迹的批处理，单次全批重建约 2.74–7.30 ms，批处理的后续重放、决策和总时间分项见 manifest。这些计时不支持线上 P95、内存或比 Direct 更快的结论。[接收器](code/receiver.py) · [实验入口](code/run_oracle_pilot.py) · [运行环境和源码哈希](results/oracle_v1/manifest.json)

## 5. 决策与文献缺口

**建议仅保留一次有针对性的同信息竞争性检验，然后作取舍。** 已知窗口、幅值只知同号区间时，精确稳健 Direct 有一个简单基准：取最靠近零的幅值端点乘以窗口响应。给定同一候选集和动作上限，它可作为重放必须面对的强基线。若负责人选择继续，优先在同一份候选范围、同一激活时刻下对照 TRSR 和 Direct，限制在停止后 0–5 拍能获得证据的情形，单列获取证据的实际等待和两法各自的增量运行成本。人工范围只作诊断。如果审计无法及时产生有效方向，或重放没有精度、风险或成本方面的独立价值，则结束 TRSR 工程开发。P2 原始数值筛选已满足，是否继续到这一检验由研究负责人决定。完整在线系统、校准后的实用竞争算法和投稿确认仍待后续证据。
