# ACK V1.0 P4：独立整数验证报告

## 验证方法

理论公式位于 ack_theory/model.py。攻击端 ack_theory/attack_oracle.py 使用独立窗口计数和阻断/放行二进制向量枚举；T2另用独立Bellman递归枚举每拍等待、发送和合法攻击反馈，比较确定性因果策略的最小最坏首成功尝试次数。两侧没有共享核心安全判断函数。证明草稿在02–04，有限穷举不能代替一般证明。

~~~powershell
python -B reviews/ack_budget_v1_theory/ack_theory/theorem_checks.py
python -B reviews/ack_budget_v1_theory/ack_theory/export_cases.py
~~~

第二条命令重建本目录data下两个压缩结果，不调用旧实验或随机数。

| 检查 | 范围和结果 |
|---|---|
| T1 | 40,858 个任意机会集合；两套窗口计算及攻击向量枚举一致 |
| T2 | 3,295 个合法历史/截止实例；最小安全集合、因果Bellman博弈与公式一致 |
| T3 | 同3,295实例；前沿、含∞的单调性、安全和成本中性边界一致 |
| 滑窗参数 | L=2,…,10；每个L均覆盖B=0,…,L−1 |
| 主穷举历史/截止 | k=1,…,4；任务长度1,…,5；逐一穷举该范围的历史和未来机会子集，过滤非法历史 |
| 长窗补充 | 720个案例，覆盖每个L/B、较长历史、任务跨越L、连续/稀疏/空机会及历史失效；仅代表性选取，并非全子集 |
| 语义回归测试 | 7项通过：稀疏机会、空集合、零预算、预算耗尽、不可行截止、相同失败数不同时间戳、超长任务 |
| 随机轨迹和Monte Carlo | 0 |

逐例文件 [all_exhaustive_cases.jsonl.gz](data/all_exhaustive_cases.jsonl.gz) 每行包含L/B/k/D、历史阻断、发送机会、每个窗口U与N、理论判断、合法攻击向量数/全阻断向量数、攻击判定、Bellman结果和前沿。长任务另存 [long_horizon_boundary_cases.jsonl.gz](data/long_horizon_boundary_cases.jsonl.gz)。汇总为 [exhaustive_validation.json](data/exhaustive_validation.json)。

**限制。** 主穷举没有覆盖所有长度的历史/任务；长窗部分不是全穷举。数字只验证这些离散实例，不表示L=2…10下任意k与D全部穷尽。Bellman只覆盖任务书给定的持续请求、确定性因果、每拍至多一次且可以自由发送的单链路模型。

## 必须保留的失败与修正

1. 首次验证脚本把滑窗下界误写为固定 k−L+1，而不是随终点变化的 t−L+1，导致 L=2、B=1、k=1、D=3、S={1,3} 误判为安全；实际上每个长度2窗口最多包含一个机会，攻击可阻断两次。修正后通过。它是**验证脚本缺陷**，并非对T1原命题的反例。
2. 人工例子初稿曾使用时刻0作为既有阻断、或在B=0时使用非空历史，均不满足模型，已撤回并重建合法例；正式穷举始终过滤非法历史。
3. T2证明草稿曾说“早连续机会在每个窗口都比稀疏集合多”，一般不对；现在03号报告中按窗口终点在 k+m−1 前后分两类给下界证明。
4. T3最大安全等待的初稿把持续超过L拍的全部尝试计入最后一个窗口，不成立；现在04号报告按剩余次数 n≥B+1 与 n≤B 分开论证。
5. T3推导末时刻应为 k+s+m−1；不能在已定义 q=k+s 后再次加s。

这些错误和修订过程应保留，不能叙述成一次性无错证明。早先口头“通过”仅指执行者的初步核对；一般定理还需研究负责人独立验收。
