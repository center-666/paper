## 2. 网络、参与者与时间

**FACT〔668 / PDF2，§2.1，无式号〕。** 至多 N 个站点组成逻辑环，但物理竞争发生在共享信道上。同一时间至多一个消息成功；多个站点同时尝试则碰撞，信息丢失。站点有唯一 LID；动态配置另区分当前 CID。站点可 active、joining 或 inactive；active 内分 idle/ready；inactive 内分 dormant/dead。

**FACT。** 系统按时隙运行，只能在时隙开始时发起传输。单位时隙等于端到端传播延迟 τ。消息传输长度为若干单位时间，站点还进行碰撞确认和竞争搜索。因此物理时间离散，不等于每一次“竞争结果”都恰好占一个 ACK 模型时隙。图 1 的结果时刻为 0、2、3、5、7、9，不能删去间隔后冒充连续物理拍。

**FACT〔668 / PDF2，§2.1；671 / PDF5，§2.4〕。** 所有 active 站点能从共享总线获知成功帧中的信息，并一致更新自己的 NLL。joining 站点可以监听成功、空闲、碰撞，通过 Data/NLL-request/NLL 三类帧取得网络信息。正文没有 ACK-V1 那种每条边的即时可信 ACK 加局部攻击者模型；“成功已被其他站点感知”不等于定义了同一 ACK 接口。

## 3. Deadline、laxity 和 window 的精确定义

**FACT〔668 / PDF2，§2.1，无式号〕。** 消息 m 的 u_m 是完成传输所需的单位时间数；d_m 是目的端应收到该消息的绝对截止。定义

\[
l_m=d_m-u_m,\qquad x_m(t)=l_m-t=d_m-u_m-t.
\tag{Z1，原文无式号}
\]

l_m 是最迟发送时刻，x_m 是在不导致截止过期前可延后的时间。站点 s 的队列 q(s) 给出

\[
X_s(t)=\min_{m\in q(s)}x_m(t),\qquad
L_s=\min_{m\in q(s)}\{l_m\mid l_m>0\}.
\tag{Z2，原文无式号}
\]

空队列的代数最小值没有在此处另作完整定义；其 idle 行为由状态描述处理。新消息可改变 X_s、L_s。

**FACT〔668–669 / PDF2–3〕。** 竞争窗口为整数边界 w=[Low,Up)，用来搜索最小 latest-time-to-send 所在的区间。它是**消息优先值/最迟发送时刻的搜索区间**，既不是最近固定 L 个物理拍的失败计数窗，也不是最近 L 次传输的擦除窗。虽然边界具有时间量纲，也不能将其宽度直接当成 ACK 的固定 L。

**FACT〔669 / PDF3，§2.2〕。** 当前 t 下，站点资格为

\[
E_w(t)=\{s\text{ ready}:L_s\in[t,Up)\}.
\tag{Z3，原文无式号}
\]

资格下界扩展到当前时间 t，而不总是 Low，目的是容纳竞争期间新到达、优先值更小的消息。每拍清除最迟发送时间已过的消息，并从 NLL 清除小于当前时间的值。

## 4. NLL 的内容与三个结果分支

**FACT〔668 / PDF2，§2.1〕。** Network Laxity List 的条目是发生碰撞的窗口上界，或某站最近被全局获知的 G_s；G_s 一般不同于该站当前的 L_s。它不是“阻断发生时刻”列表，没有固定 h+L 的失败记忆过期规则。

| 结果 | 触发条件及实际发送 | 原文更新 | 定位 |
|---|---|---|---|
| 成功 | 恰一个站点有资格并发送 | 成功帧携带该站下一 L_s；更新 NLL；新竞争阶段从 [t,top(NLL)) 开始 | 669 / PDF3，§2.2 |
| 碰撞 | 多于一个站点有资格并同时发送 | 记录旧 Up，搜索区间缩小 | 同上 |
| 空闲 | 没有站点有资格，无人发送 | 调整区间继续寻找候选；正文仍称当前窗口 failed | 668–669 / PDF2–3，§2.2 |

碰撞后的式子为

\[
Up'=\left\lceil\frac{Low+Up}{2}\right\rceil.
\tag{Z4，669 / PDF3，原文无式号}
\]

空闲后的边界更新为

\[
Low'=Up,\qquad
Up'=\left\lceil\frac{Up+top(NLL)}{2}\right\rceil.
\tag{Z5，669 / PDF3，原文无式号}
\]

**FACT。** 669 页给出 NLL 清空时的 initial phase：active 站点一旦 ready 可在下一拍尝试；若碰撞则建立初始竞争窗。暂定窗口在空闲时倍增，直到成功或碰撞，再进入搜索。正文未规定一个像 (τ=0,H=∅) 那样的唯一全局初态，也未完整给出初始窗口宽度的统一数值。

**FACT / OPEN。** 成功会开始新的竞争 epoch，并更新最后成功站点身份 v；已有 NLL 信息不简单全部清空。但正文不足以把每项 NLL 弹出、空队列公告值及相等端点处理恢复为无歧义的逐行代码。图 1/2 给出具体轨迹，足以核对基本分支，却不能据此自行补全所有实现边界。这不影响本文已明确的事件和窗口语义。

## 5. Tie Assessment Phase 与全部编号性质

**FACT〔669 / PDF3，§2.3〕。** 当单位宽度窗口 [Low,Low+1) 的结果仍为碰撞时，进入 TAP。其目标是在最小 laxity 的多个站点中确定唯一发送者。逻辑子环和相对上次成功站点的位置用于确定次序，而不是按某个攻击预算保证本边重试成功。

**FACT〔670 / PDF4，§2.3.1〕。** v 是最近成功发送站点的 ID，n 是候选站点 ID；候选优先值 l 位于当前 t 至 Low。原文同时用 L 指 ID 集合及算式中的环规模。为消除与 ACK 的 L 混淆，本报告在算式中以 M 表示活动环规模，ID 取 0,…,M−1。原文的环距离及竞争参数为

\[
d(n,v)=(M-v+n)\bmod M,
\tag{Z6，670 / PDF4，原文无式号}
\]

\[
t_v(n,l)=Ml-((M-d(n,v))\bmod M).
\tag{Z7，671 / PDF5，Theorem 1 内公式}
\]

**FACT〔671 / PDF5〕。** P1、P2 要求不同站点/不同 l 的唯一性；P3 为相对环距离的公平性；P4、P5 为 l 的次序保持；P6、P7 为参数区间连续性。**Theorem 1** 声称 Z7 满足全部性质，并引向参考文献 [6]，本篇没有展开完整证明。本轮不阅读范围外的 [6]，也不伪造其证明。

原文性质的数学内容逐项记录为：

| 原编号 | 印刷表达 / 条件 |
|---|---|
| P1 | n1≠n2 ⇒ t_v(n1,l)≠t_v(n2,l) |
| P2 | l1≠l2 ⇒ t_v(n,l1)≠t_v(n,l2) |
| P3 | d(n1,v)<d(n2,v) ⇒ t_v(n1,l)>t_v(n2,l) |
| P4 | l1>l2 ⇒ t_v(n,l1)>t_v(n,l2) |
| P5 | l_i>l_j ⇒ t_v(n_i,l_i)>t_v(n_j,l_j) |
| P6 | d(n1,n2)=1 ⇒ abs(t_v(n1,l)−t_v(n2,l))=1 |
| P7 | min_i t_v(l,n_i)−max_j t_v(l−1,n_j)=1；此处原文参数次序与定理 1 的 t_v(n,l) 写法相反 |

**OPEN。** P7 的次序差异不能静默忽略。下节证明的是按 latest-time 等级排列的相邻数值块连续性，不声称其字面反序调用在全部定义域都正确。

**FACT。** **Theorem 2** 声称协议实现 minimum-laxity-first。印刷证明是：在单位窗碰撞时计算唯一竞争参数；P1、P2、P4、P5 保持唯一性与 laxity 优先。它没有证明任意负载下所有报文必按期送达，也没有给出任意攻击下的固定截止成功或最坏尝试次数。

### 5.1 本轮独立代数核对及原文边界

**DERIVED。** 对固定 l，令 r_v(n)=((M-d(n,v)) mod M)。r_v 在 0,…,M−1 上排列，因此参数恰占据

\[
\{M(l-1)+1,\ldots,Ml\}.
\]

不同 l 的块不交且相邻块间隙为 1；同一块内 ID 参数唯一。故 Z7 确实给出唯一排序，且较小 l 的所有参数都小于较大 l 的参数。这严格支持 P1、P2、P4、P5 及相邻 laxity 块连续性；选择最小参数会先选较小 l。这个性质处理的是优先排序，不是历史失败窗口。

**FACT / DERIVED。** 671 页放大图确认 P3 印为 d(n1,v)<d(n2,v) 时 t_v(n1,l)>t_v(n2,l)。取 M=4,v=0,l=10，Z7 给 t_v(1,10)=37、t_v(2,10)=38，方向与印刷 P3 相反。P6 原样要求循环相邻 ID 的参数差为 1；同参数取 n1=1,n2=0，d(1,0)=1，但参数差 |37−40|=3。因此不能无条件认领“Theorem 1 的全部印刷性质已逐条证成”。

**HYPOTHESIS / OPEN。** P3 可能是方向排印问题，P6 可能意指不跨线性排序切口的相邻关系；尚无本轮核实的勘误，不能把猜测当成原文更正。Theorem 2 印刷证明只调用 P1、P2、P4、P5，上述歧义不取消已核的优先排序结构，更不能作为 ACK 创新性的替代证据。

## 6. 加入、统计模型与保证的边界

**FACT〔671 / PDF5，§2.4〕。** joining 站点需取得 NLL；可以听取完整帧或持续空闲后，比较本地 L_s 与公告 top(NLL)，通过请求帧请下一成功站点广播 NLL。成员加入与故障识别需要共享信道信息，非单条链路仅观察本地 ACK 的接口。

**FACT〔671–672 / PDF5–6，§3〕。** 性能实验使用各类 Poisson 消息到达，负载写成

\[
\rho=\sum_{i=0}^{N-1}\sum_{j=0}^{C-1}\lambda_{ij}\bar x_{ij}
=\bar\lambda\bar x.
\tag{Z8，原文无式号}
\]

实验固定正常工作的站点及无传输介质错误，比较丢失消息、有效利用率、延迟。原文的 message-loss-percentage 分母文字写作该类成功发送消息数，不能未经核对就当成 ACK 的标准尝试失败率。表 1 和图 3–5 是原论文实验，不是本项目验证；本轮没有运行任何模拟。

**DERIVED。** 最小 laxity 排序不等于所有截止可满足：同一单信道上若同时到达两个 u=1、截止均为当前时刻后一单位的消息，容量不足以使二者都按期完成。这个容量反例不反驳 Theorem 2 的排序结论，只排除把其“optimal”措辞扩大为任意负载的必达保证。原文也明确清除过期消息并报告延迟/丢失。

## 7. 原协议还原的结论

**FACT。** 本篇真正对象是共享介质上的 deadline/laxity 竞争搜索、保留信息的 NLL 和确定性 tie 处理。它存在时间槽、等待、碰撞、历史信息、成功后新竞争阶段，但没有声明 ACK-V1 的硬 (B,L) 阻断预算、自然锚点、或 s_safe>0 时对本边强制不尝试的门控。后续关系必须通过状态与事件映射证明，不能用相同的 window / deadline 名称代替。
