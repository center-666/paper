# 双容液位快速浮点实现与配对在线回放

在冻结双容液位模型上，M3-Fast 用 binary64 递推协方差、参考似然和起点响应。对每个候选起点，先将低方向支撑约束化成一段幅值区间，再按发送似然的移动零点分段。各开段内的对数似然为凹函数。程序先用中点切线上界筛查，其余各段按端点导数或内点导数零点选择极大值，利用切线核对余量。浮点门限采用预设的 10⁻⁹ 对数似然数值余量。该余量用于工程判断，形式化边界采用正文的向外舍入实现。参数、参考幅值、起点候选、查询时钟、尝试等级、方向提议和校正上限均沿用冻结双容配置。

**表 1 独立在线回放耗时 / Table 1. Standalone online replay times**

| 实现及批次 | 每 608 拍平均墙钟耗时 / s | 每 608 拍平均 CPU 耗时 / s | 查询 P50 / ms | 查询 P95 / ms |
|---|---:|---:|---:|---:|
| 原型 M3-Exact，本轮同机 | 41.21 | 26.96 | 1290.91 | 11393.15 |
| 工程 M3-Fast，本轮同机 | 0.0691 | 0.0508 | 0.464 | 31.104 |
| 原型 M3-Exact，早期归档 | 19.99 | 19.86 | 1138.5 | 4490.8 |

本轮使用原四条强偏置轨迹（正负各 2 条、编号 00/01），每个工作进程消费同一轨迹的公共帧并分别建立两法的在线状态。每法先用前 8 拍暖机，精确版在计时前清空与归档计时相同的两类缓存。按编号交换运行顺序，共四个工作进程，数值库各单线程。计时含状态初始化、每拍递推与输出、四次查询和逐拍动作哈希，排除文件读取、物理轨迹生成及事后损失核验。全流程墙钟平均来自 4 条轨迹，查询分位数来自 16 次查询。两法动作的最大坐标绝对差为 1.67×10⁻¹⁶ cm，精确版四条动作哈希均与冻结数据相符。同期机器负载可影响墙钟计时，CPU 耗时另列。工程版同时改变数值算术、数组实现和似然搜索，计时刻画这些改动的合计作用。

两法共享的 464 个查询时刻上，浮点与冻结实现的方向和逐等级签发序列均相同。其中 68 次至少签发一档。10,789 次非零动作采用真实偏置与起点从独立递推的条件均值离线评分，以 10⁻¹⁰ cm² 作浮点核对容差，均达到所报下界。该结果覆盖本次双容轨迹和已知模型。全组的出手一致率、逐轨动作哈希及四条配对计时轨迹的最大坐标偏差对应不同精度口径。

在该目录执行以下命令重建两组数据及表格数字。时间值随机器和调度变化。

```sh
python -B run.py audit
python -B run.py timing
python -B summarize.py
```

运行环境和单条分解分别见 [audit.json](audit.json) 与 [timing.json](timing.json)。历史计时来自 [冻结计时记录](../../results/timing.json)。
